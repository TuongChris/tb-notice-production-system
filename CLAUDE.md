# CLAUDE.md — TB Notice Production System

Read this first in every session. It summarizes binding decisions; the documents it points to are authoritative.

## Product boundary

- Internal, local-first tool that prepares a case-specific **unsigned** YouTube copyright notice or NMI reply from structured facts and attributable sources.
- Terminal output is an unsigned `NoticeCandidate` with the single pending slot `[PENDING AUTHORIZED SIGNER — FULL LEGAL NAME REQUIRED]`. `READY_FOR_SIGNER` is **derived**, never a column, never a PATCH/UI action.
- A human signer reviews, adopts, signs and sends **outside** the app. There is no G7, signing, sending, email/SMTP, Drive writing, uploader contact or AI-provider API — do not add them.
- Technical validation (`ValidationRun`) is not substantive review; G1–G6 are separate sourced `CandidateAssessment`s.
- Gate terminology (permanent; R14-AUD-008): G1 authority/standing · G2 work-specific rights · G3 reported-material identification · G4 evidence/audiovisual comparison · G5 permission/copyright exceptions · G6 exact candidate artifact consistency, traceability and whole-artifact QA (supported prose, material NMI asks where applicable) · G7 the actual authorized human review, adoption, signature and sending act, outside the application. AI cannot satisfy G7; personal adoption is G7, never G6.
- Google Drive holds canonical evidence; the app DB holds working data, references and snapshots. Git is not an evidence archive: never commit real case/owner/authority data, LOAs, raw mail, tokens or secrets. Fixtures are synthetic only.

## Authentication (P1; details `docs/verification/p1/P1_AUTH_SHELL.md`)

- An application User is **not** a Signer: login confers no legal authority, satisfies no G1–G7 gate and signs/adopts/sends nothing. No signup or user-management endpoint.
- Accounts only through the local admin CLI (`yarn admin:create | admin:password | admin:disable | admin:enable | admin:revoke-sessions`): allowlist-guarded to `tb_notice_dev` with the `tb_dev` account in the wrapper and again in the compiled entry; passwords via hidden prompt or `--password-stdin` (pipe/file only), never argv/env; `create` never modifies an existing user and recovery commands never create one; every change plus its audit event is one transaction and state changes increment `session_epoch`. The P0 synthetic actor and non-credential (`!`) fixtures are never modified (disable only reports). Never create, recover or change a real account on the operator's behalf; tests use synthetic users in `tb_notice_test`.
- Sessions: 256-bit opaque token only in cookie `tb_session_dev` (HttpOnly, SameSite=Strict, Path=/, no Domain; Secure=false is the loopback-HTTP dev exception only). DB stores SHA-256 digests. 12 h absolute + 30 min idle; login rotates; logout revokes.
- CSRF token = HMAC-SHA256(`TB_SESSION_SECRET`, session id ‖ `users.session_epoch` ‖ token); incrementing the epoch (or rotating the secret) invalidates sessions. Unsafe methods need an exact allowlisted Origin (`TB_ALLOWED_WEB_ORIGINS`: canonical Windows browser `http://localhost:5173`, plus `http://127.0.0.1:5173` for WSL tools; cookies are per hostname, never shared), JSON bodies and `X-CSRF-Token`; login needs the Origin plus `X-Requested-With: TB-APP`. CORS is never enabled.
- Credential failures are one identical `403 INVALID_CREDENTIALS`; in-memory throttle (5/account, 100 overall per 15 min). Never log or store passwords, tokens, CSRF tokens or their hashes; every API response is `Cache-Control: no-store`. These P1 decisions were accepted at R4 (PASS_WITH_NOTES); session-row retention is DEFERRED.
- The production cookie (`__Host-tb_session`, Secure, HTTPS) is not implemented; a non-loopback or HTTPS origin makes the API refuse to start. Do not reuse the dev exception.

## Directory and business writes (P2; details `docs/verification/p2/P2_DIRECTORY.md`)

- Every contracted write goes through `WriteExecutor` (`apps/api/src/infrastructure/write`): contract body parse (422) → `Idempotency-Key` (400) → `If-Match` when the contract declares `x-precondition-target` (428 missing, 412 unless byte-identical to `"<Type>:<id>:v<rowVersion>"`) → idempotency claim → one READ COMMITTED transaction (row locks in alphabetical entity order, business rules, change with `rowVersion` +1, audit event, idempotency completion) → bounded deadlock retry (3). Failures release the claim; never store a failed request as a replay. Method, path and precondition target come from `@tb/contracts`, never hand-typed.
- Dates and instants (R7, all phases): every DATE / DATETIME(3) value from a request goes through `apps/api/src/infrastructure/write/storability.ts` — refused with 422 `VALIDATION_FAILED` before any idempotency claim or write unless the column stores and reads back exactly the same value (no leap second, no hour 24 or minute overflow, no non-zero digit after the milliseconds; UTC `1000-01-01T00:00:00.000Z`…`9999-12-31T23:59:59.499Z`, MySQL's supported DATETIME range with a fraction; DATE `1000-01-01`…`9999-12-31`), and written as the exact `Date` it computes (`toDbInstant`), never the request string: Prisma's and V8's string parsers disagree with the wire oracle (500s, cut fractions, shifted years). Never add a second date validator.
- Idempotency scope is actor + operationId + key; the digest covers operation, method, contract path and canonical body (not If-Match); replay horizon 7 days; 60 s lease for abandoned claims.
- Lists: keyset `(createdAt DESC, id DESC)`, default 25 / max 100, HMAC cursors bound to operation, scope and filters (400 `INVALID_CURSOR`). Only declared query parameters.
- Established Agency/LegalSubject (ACTIVE, canonically bound, or referenced through any FK or JSON snapshot/scope column — an agency-owned SourceReference counts, R6): **every** identity-defining field is immutable through generic PATCH — populated, null or empty (R5). Correcting or supplementing an established identity needs a future dedicated workflow with source/provenance/audit; do not invent it. Hard delete only for unused, unbound DRAFT records. Archived records are read-only except the explicit restore, which returns DRAFT and revives nothing.
- Signer operational state is administrative only: no state implies mandate coverage, eligibility, G7, signature authority or notice adoption.
- Accent-insensitive collation (`utf8mb4_0900_ai_ci`) is only for `q` discovery search (LIKE); never for identity equality, canonical matching, duplicate determination, unique keys or legal/entity equivalence (a test scans the API source).
- SourceReferences are created only by `createSource`/`reviseSource` (P3A); never create one (or a placeholder) from directory, route or binding code. Every cited source must exist and apply to the record (`modules/sources/source-scope.ts`, below). Provenance is stored as given, never upgraded.
- A new FK or JSON column must be added to `DIRECT_REFERENCES` / `SNAPSHOT_JSON_COLUMNS` in `modules/directory/records.ts`; a test parses the migration and fails otherwise.
- No generic BaseCrud: shared mechanics only (write executor, ETag, idempotency, cursor, audit writer); entity rules stay explicit per service.
- UI: capabilities that are not available (source attachment for attributions, Signer sources and link sources, known-ineligible delete) stay visible but inert (`aria-disabled` + reason); never simulate success. No new UI dependencies without a decision.
- Browser checks run only against `yarn ui:sandbox` (compiled API on `tb_notice_test`, synthetic user, full cleanup); never against `tb_notice_dev` or with a personal browser profile. Its cleanup is armed only after the run itself verified an empty `tb_notice_test` (`scripts/local/sandbox-lifecycle.ts`, R14-AUD-004): a refused start, an error or a signal before that updates or deletes nothing.

## Sources, canonical bindings and routes (P3A, R6 PASS, merged to `main`; details `docs/verification/p3a/P3A_SOURCES_ROUTE.md`)

- A SourceReference is an immutable pointer with capture metadata (no PATCH, no ETag) — not evidence, review proof, permission or authority; Drive keeps the evidence. Store exactly what was supplied: omitted `accessState`/`reportedProvenance` default to NOT_CHECKED/OPERATOR_REPORTED; never fetch the URL, compute or invent a hash (a hash needs its `hashTarget`), infer provenance or add provenance values; DOCUMENT_REVIEWED needs `reviewedByLabel`; `caseIds` name existing, unarchived cases, and an agency's own source only its own agency's cases (P4A); `observedAt`/`reviewedAt` are stored as exactly the supplied instant or refused (R7 storability rule; on `main` since the P3B merge `3649bef`). Audit keeps metadata only (scope text, excerpt, limitations as `{redacted, codePoints}`).
- DOCUMENT_REVIEWED (permanent rule, R6): a SourceReference row does not itself establish it. It means an actual human review of the document occurred and is recorded only from an explicit, supported, human-entered fact representing that review. A reviewer name, URL, source row, hash or canonical binding never by itself upgrades provenance; defaults never upgrade.
- Revisions: only the current head is revised (409 `REVISION_NOT_HEAD`); a revision keeps `agencyId` and `scopeBindings` (422 `REVISION_SCOPE_CHANGE`), never changes earlier revisions and never re-points bindings; lists show current heads only.
- Applicability (one rule set for attributions, Signer sources, link sources and bindings): Agency, Signer and Route need their agency's own source or an agency-less source naming the agency in `scopeBindings.agencyIds`; Owner, LegalSubject and OwnerSubject need an agency-less, unrestricted source; a LegalSubject must be named, a subject-scoped source for a Route/OwnerSubject must name its subject, an Owner refuses subject-scoped sources; material recorded for one Owner never supports another (`CROSS_OWNER_REFERENCE`); a case-scoped source applies only to the cases it names and to no directory, route or authority record (P4A).
- Canonical binding = identity/reference only (no ownership, authority, mandate, eligibility, G1–G7 or readiness): current revision, role CANONICAL_RECORD, applicable scope, code unique per kind (binary), archived targets refused, an existing binding is never replaced (409 `BINDING_CORRECTION_REQUIRES_RECONCILIATION`; no reconciliation workflow exists — do not invent it); DIVERGENT is never set. A bound Agency/LegalSubject is established (identity lock); a bound Signer's `fullLegalName` locks.
- Route = Agency + OwnerSubject + YOUTUBE, not authority: explicit, existing, unarchived parties and a LINKED association; one per (agency, association, platform); PATCH cannot move it; `defaultSignerId` = a non-archived, non-ENDED Signer of the same agency; non-null `preferredCoverageId` → 422 `PREFERRED_COVERAGE_UNAVAILABLE` until P3B; LINKED needs unarchived parties and a LINKED association; archive is a separate flag and restore is refused while a party is archived; delete only unused routes.
- OwnerSubject with an archived Owner or LegalSubject (R5 closeout rule): no new link and no relink; PAUSE and UNLINK stay allowed; the row is never deleted.
- Never show AUTHORIZED, READY, ELIGIBLE, G1 PASS or "verified" badges for sources, bindings or routes. `smoke:p3a` writes records and runs only in CI.

## Representation authority (P3B, R7 PASS, merged to `main`; details `docs/verification/p3b/P3B_REPRESENTATION_AUTHORITY.md`, R7 §21–§22)

Persistent rules (never weaken; UI copy follows them):

- **Authority records are not self-proving.** A Mandate, MandateVersion, MandateCoverage, CoverageSigner or AuthorityEvent records what cited sources are reported to support; existing, completeness, a frozen state or being the latest proves nothing.
- **A frozen version is not approval.** FROZEN = the system record is immutable; not a signature, legal approval, owner confirmation, G1 decision, notice adoption or current authority. No unfreeze; every later change of the version or its coverage/signers is 409 `FROZEN_VERSION`; a correction is a successor version.
- **Coverage ≠ G1.** A coverage is the documented scope of one version over one exact Route, stored exactly as supplied and never derived; case authority is determined later.
- **CoverageSigner ≠ G7.** A Signer recorded under one coverage (same agency, not archived or ENDED; duplicates refused); not signature authority, G7 clearance or eligibility; never transfers to another coverage, route or case. An application User is never a Signer. Wording: "Associated signer", "Coverage signer", "Recorded under this coverage" — never AUTHORIZED/APPROVED SIGNER, READY TO SIGN or ELIGIBLE FOR NOTICE.
- **An AuthorityEvent is not proof by existence.** Append-only (no ETag, update or delete), exactly as reported with an explicit provenance; nothing creates one automatically; recordedAt is never an effective date; supersession keeps mandate and scope, at most one successor, the earlier event unchanged.
- **Source revision pinning.** Versions, coverages, signers and events cite exact SourceReference revisions and never follow a newer one.
- **No currentness from dates or silence.** Nothing computes "currently authorized" — not from dates, a frozen state, the highest version, a missing end date, a missing event or the latest source. Dates are stored only as supplied; start > end is 422 `DATE_RANGE_INVALID`.

Implementation rules:

- Mandate = container of one Agency (agency fixed; no identity lock; archive is a flag — an archived mandate and everything under it are read-only except restore; an archived Agency blocks new authority records, freeze and restore; delete only unused).
- Versions: number max+1; predecessor = FROZEN version of the same mandate without a successor (no fork, no cycle); DRAFT-only edits; DRAFT/SIGNED_APPEARING need the primary source; REVIEWED_WITH_LIMITS and a DOCUMENT_REVIEWED event need a cited source recorded as DOCUMENT_REVIEWED — citing one never upgrades anything.
- Parent ETags cover children: create version / record event increment the Mandate; coverage and signer changes increment the version (signers also the coverage). Freeze locks the version FOR UPDATE, re-validates the structure, changes the version once and audits once.
- `Route.preferredCoverageId` = frozen coverage of the same route in an unarchived mandate (operational default only; no cascade on a later archive — R7: the recorded preference is kept, and any later Case/authority-selection workflow must revalidate that the coverage is usable).
- R7 decisions (accepted): no identity lock on a Mandate (a representation/appointment container, not a LegalSubject identity); an archived Mandate records no new event — a historical or retroactive event is recorded by restoring it administratively, recording the event with its actual supplied effective/occurred date and archiving again if appropriate (`recordedAt` never replaces `effectiveAt`); UNTIL_TERMINATED with an `expiresOn` is preserved as supplied, with no currentness, expiry or contradiction resolution inferred; PAUSED Routes and Signers may take part where the contract allows (administrative state, not legal authority); a truthful incomplete DRAFT version may be frozen (immutable snapshot only — not complete, approved, current, G1 PASS, owner-confirmed or signer-adopted); the conservative owner-material scope extension stays until an explicit owner-scope model exists. No contract amendment is authorized by them.
- Source applicability: mandate context (Agency) for version and whole-mandate event citations; route context for coverage basis, signer and coverage-scoped event sources, which also count as that route owner's material (`CROSS_OWNER_REFERENCE`).
- Error codes: frozen stable codes where they fit; P3B implementation codes `VERSION_NOT_FROZEN`, `VERSION_SUCCESSOR_EXISTS`, `DATE_RANGE_INVALID`, `DOCUMENT_STATE_UNSUPPORTED`, `REVIEW_UNSUPPORTED`, `DUPLICATE_COVERAGE`, `DUPLICATE_COVERAGE_SIGNER`, `EVENT_ALREADY_SUPERSEDED` (free-string `code`, contracted statuses). `PREFERRED_COVERAGE_UNAVAILABLE` is retired.
- Never show AUTHORIZED, APPROVED, VALID, CURRENT AUTHORITY, READY, ELIGIBLE or G1/G7 PASS labels for authority records. `smoke:p3b` writes records and runs only in CI.

## Cases, case sources and authority selection (P4A, R8 PASS — first PASS_WITH_ONE_CONTRACT_REMEDIATION, then PASS at R8 final; VERIFIED_COMPLETE, merged to `main`; details `docs/verification/p4a/P4A_CASE_CORE.md`, §21–§23)

Persistent rules (never weaken; UI copy follows them):

- **Case isolation.** A case is the boundary of its case-specific records: nothing recorded for one case (source links, selections, canonical id, workflow or archive state, case-scoped sources) supports, appears in or carries over to another case. A case-scoped source applies only to the cases it names (422 `CROSS_CASE_REFERENCE`). Case pages are rebuilt per case (React `key` on the case id).
- **A CaseSource link is not proof.** A link records only that one exact source revision is associated with one case in a role — never reviewed, true, proven, permitted or authoritative — and it never changes provenance. Wording: "Linked source", "Recorded provenance", "Source reference"; never "Evidence proves…".
- **CaseAuthoritySelection ≠ G1.** "The authority chain selected/pinned for evaluation in this specific Case" — never G1 PASS, confirmed current authority, adjudicated validity, signer eligibility, G7 or readiness. UI: "Selected authority record" and "This selection records which authority materials will be evaluated for this Case. It is not a G1 decision."; never AUTHORIZED, G1 PASS, VALID AUTHORITY or APPROVED badges.
- **Exact selection pinning.** A selection pins the exact route (the case's bound route), signer, coverages of FROZEN versions that record that signer (each with its own application scope) and basis source revision, and never follows a newer version, source revision, default signer or preferred coverage. Append-only: a new selection moves the case's pointer; earlier selections and their CaseAuthorityCoverage rows never change; a case with history keeps its route (409 `BINDING_CORRECTION_REQUIRES_RECONCILIATION`).
- **No cross-case inheritance, no implicit selection.** Nothing is selected or inherited from another case, the route's default signer or preferred coverage, the latest, frozen or only version, a missing end date, the same agency or matching names; nothing auto-selects and no currentness is computed.
- **No readiness in P4A.** Nothing computes G1–G7, READY_FOR_SIGNER or readiness, and no workflow state implies any of them.

Implementation rules:

- Case: agency, platform (YOUTUBE) and class are fixed at creation; PATCH = intake label, owner hint, packet source, Drive folder, notes; route, canonical id, workflow, archive and selection change only through their commands. `rowVersion` moves with every change, `contextRevision` with what the case relies on (route, canonical id, links and their states, selection, intake label, owner hint, packet source, Drive folder) — not the notes (reconciled at R11: the label has always moved it, `MATERIAL_PATCH_FIELDS`; `P4A_CASE_CORE.md` §24). With a bound route the owner hint is null or that route's owner (422 `CROSS_OWNER_REFERENCE`).
- Route binding: a LINKED, unarchived route of the case's agency with usable parties; a correction only before history (selection, fact, prompt, correspondence, candidate), re-checking every source the case relies on. Canonical binding: the P3A rules with the case as target; never replaced.
- Workflow: any state to any other with a reason (the same state is 409); CLOSED records `closedAt`/`closeReason` and reopening clears them; no gate and no legal meaning. Archive is a flag (read-only except restore; restore is refused while the agency or the bound route is archived and revives nothing). Delete only an unused case (not archived, no canonical binding, no FK or JSON reference → otherwise 409 `REFERENCED_RECORD_CANNOT_DELETE`); never delete dependencies to make room.
- CaseSource: one row per (case, source, role) (409 `DUPLICATE_CASE_SOURCE`); the revision stays pinned; link state LINKED/PAUSED/UNLINKED with a reason and the link's own ETag; relinking re-checks the scope; links and sources are never deleted.
- Source scope for a case (`modules/sources/source-scope.ts`, mirrored in `apps/web/src/app/sources/scope.ts`): the case dimension above (naming the case never overrides an agency's own source or an agency restriction); otherwise the agency rule of an agency record; a subject-scoped source needs a bound route naming its subject (`CASE_SUBJECT_UNBOUND` without one); with a route, another owner's material is refused. `createSource` may name existing, unarchived cases (an agency's own source only its agency's cases); `CASE_SCOPE_UNAVAILABLE` is retired.
- Selection checks: the case is unarchived with a bound route and `routeId` is that route; the signer acts for the case's agency and is not archived or ENDED; 1–20 distinct coverages of the case's agency and route, in a FROZEN version of an unarchived mandate and agency, each recording the signer; the basis source applies to the case. `taskType` is stored as supplied (no action-scope mapping). A selection has no ETag; audit keeps notes and application scopes only as their length.
- Selection read-back (R8 remediation, TB-SCHEMA-API-v1.1.0): `getCaseAuthoritySelection` returns exactly the stored selection and its stored CaseAuthorityCoverage rows (`coverageId`, `applicationScope` as recorded, ascending `coverageId`), found only by the path's case + selection id (another case's selection is 404 like an unknown one); read-only, no ETag. Nothing is resolved, followed (preferred coverage, newer version or source revision), unioned or recomputed from present-day state; it means only "the exact authority chain selected/pinned for evaluation in this Case" — never G1, current authority, eligibility, G7 or readiness. No other route or wire field without an approved contract release.
- Error codes: frozen stable codes where they fit (`CROSS_CASE_REFERENCE` is one); P4A implementation code `DUPLICATE_CASE_SOURCE` (free-string `code`, contracted status). `smoke:p4a` writes records and runs only in CI.

## Case intake material (P4B, R9 PASS — first PASS_WITH_ONE_CONTRACT_REMEDIATION, then PASS at R9 final; VERIFIED_COMPLETE, merged to `main`; details `docs/verification/p4b/P4B_CASE_INTAKE.md`, §24–§26)

Persistent rules (never weaken; UI copy follows them):

- **ReportedItem ≠ infringement finding.** It identifies one reported YouTube video item of one case — never that copying or infringement occurred, that permission is absent, who uploaded it or who owns anything.
- **CaseWork ≠ ownership proof.** A work named for one case establishes no ownership, authorship, registration, standing or G2; rights assertions are separate, scoped CaseFacts.
- **UseMapping ≠ infringement finding.** It records, as entered, which part of one work is reported to appear in which part of one reported item of the same case — never copying, infringement or audiovisual identity. Wording: "shown as recorded, not as an infringement verdict".
- **CaseFact = explicit, case-specific, structured information**, recorded by an operator with its provenance exactly as supplied — never manufactured from a URL, a publication, a mapping, similarity, silence or a source's existence.
- **Permission is never inferred from silence; similarity alone is never infringement.** No permission source found is not "no permission"; equal durations, matching endpoints or an AV_COMPARISON record prove nothing by themselves.
- **Facts never cross Case boundaries.** Intake records are read and written only through their own case (another case's is 404 exactly like an unknown one); a record named in a body must be of this case (422 `CROSS_CASE_REFERENCE`); nothing of one case is used, copied or inherited by another; intake pages are rebuilt per case (React `key`).
- **Revisions preserve history.** A fact is revised only at its current head (409 `REVISION_NOT_HEAD` naming the head), with the chain's type and scope (422 `REVISION_SCOPE_CHANGE`); earlier revisions and their supports never change and stay readable.
- **Source and provenance are pinned.** A fact support names a LINKED CaseSource of this case (and so its exact source revision), a mapping's basis its exact revision; a newer revision re-points nothing. Provenance is stored as supplied and never upgraded — DOCUMENT_REVIEWED only with a cited source that itself records a review (422 `REVIEW_UNSUPPORTED`); the resolution state is as supplied or UNASSESSED, never SUPPORTED_FOR_SCOPE automatically.
- **No readiness in P4B.** Nothing computes G1–G7, READY_FOR_SIGNER or readiness, and no intake record or state implies any of them.

Implementation rules:

- ReportedItem: `rawUrl` exactly as supplied; `externalItemId` and `normalizedUrl` from the closed, offline recognizer `modules/cases/reported-url.ts` — `(www.|m.)youtube.com/watch` with exactly one literal `v`, `/shorts/<id>`, `/live/<id>`, `youtu.be/<id>`; an 11-character id whose case is kept; `https://www.youtube.com/watch?v=<id>`. Anything else is 422 `REPORTED_URL_UNSUPPORTED` with a reason — never guessed, nothing fetched. One item per video within a case (409 `DUPLICATE_REPORTED_ITEM`), never globally. PATCH = title and observedAt (R7 storability).
- CaseWork: the five fields exactly as supplied; no owner or rights inference; no de-duplication by title or URL. A work's notes alone are not case context.
- UseMapping: one work and one item of this case (composite foreign keys are the backstop) and an explicit occurrence (409 `DUPLICATE_USE_MAPPING` per work, item and occurrence); unsigned millisecond decimal strings ≤ 9007199254740991 (BIGINT, never SQL TIME); unknown bounds stay null; a known end must exceed its known start (422 `TIME_RANGE_INVALID`, checked on the merged state of a PATCH); `rawTimecodes` as supplied; `boundaryConvention` UNKNOWN (default), HALF_OPEN or INCLUSIVE; provenance default MISSING. Work, item and occurrence never change.
- CaseFact: the nine contracted fact types with their typed values; scope CASE (no record) or WORK / REPORTED_ITEM / USE naming exactly that record (422 `FACT_SCOPE_INVALID`); immutable (no ETag); the list shows chain heads (`q=<factGroupId>` finds a chain's head), get returns any revision of the case; supports are LINKED case sources of this case, each (link, role) once; DUPLICATE_REVIEW names only other existing cases (nothing of them is read; the related case counts as referenced).
- Writes: the case's If-Match for the three creates and both fact writes, the record's own for patch, archive and restore. Every write locks the case first (lock order CaseRecord → CaseSource → CaseWork → ReportedItem → UseMapping → CaseFact → SourceReference) and moves its `rowVersion`; `contextRevision` moves with every material change (all but a work's notes; no-ops and reads write nothing). Archive is an administrative flag with a reason and no cascade; archived records are read-only except restore and cannot be named by a new mapping or fact; a mapping is not edited or restored while its work or item is archived. A route correction also re-checks every unarchived mapping's basis source. Audit keeps quoting free text only as its length.
- Fact-support read-back (R9 remediation, TB-SCHEMA-API-v1.2.0, ADR-0005 ACCEPTED at R9 final): `getCaseFactSources` (GET `/cases/{caseId}/facts/{id}/sources`) returns exactly the stored FactSource rows of that one revision of this case (`id`, `factId`, `caseSourceId`, `supportRole`, `supportedAssertion`, `createdAt`, `createdById`) in ascending `(createdAt, id)` order — never a semantic order. Zero rows is a normal answer (`sources: []`: not unsupported, false or MISSING; the R8 one-row rule does not apply). Rows are never merged across revisions, never hidden after the link is paused or unlinked (the link's present state is read separately and shown apart) and never follow a newer source revision. Another case's fact is 404 like an unknown one; read-only (no ETag, no write, no audit); a stored row naming another case's link or more than 100 rows is a 500, never shown. It means only "the exact source-support rows recorded for this exact CaseFact revision" — never proof, DOCUMENT_REVIEWED, SUPPORTED_FOR_SCOPE, a finding, G1–G7 or readiness. `getCaseFact` stays unchanged. Never parse audit events, remember supports client-side or query the database from the UI instead.
- Error codes: P4B implementation codes `REPORTED_URL_UNSUPPORTED`, `DUPLICATE_REPORTED_ITEM`, `DUPLICATE_USE_MAPPING`, `TIME_RANGE_INVALID`, `FACT_SCOPE_INVALID` (free-string `code`, contracted statuses). `smoke:p4b` writes records and runs only in CI.

## Correspondence (P4C, R10 PASS; VERIFIED_COMPLETE, merged to `main`; details `docs/verification/p4c/P4C_CORRESPONDENCE.md`, §29–§30)

Persistent rules (never weaken; UI copy follows them):

- **Capture ≠ send.** Capturing records one past communication exactly as supplied. It sends, replies, acknowledges, marks read, fetches, contacts or submits nothing, and proves no transmission, receipt, authenticity or outcome.
- **OUTBOUND ≠ AS_SENT.** A direction records only which way a message went. An AS_SENT event exists only when the operator binds it explicitly; nothing is inferred from the direction, and no event type requires one.
- **An event type names a captured past event.** It is the operator's interpretation, never a command; recording one causes nothing.
- **OPERATOR_REPORTED never becomes raw-source verification.** `captureMode` and `bodyRole` are stored as supplied and never upgraded. No raw file, provider receipt, raw-MIME hash or attachment observation is implied.
- **Message-ID and subject are not identity.** Nothing is deduplicated, merged or matched by Message-ID, subject, references, addresses or dates. `sourceIdentityHash` stays null until a reliable provider or capture identity exists.
- **One message with several bindings is not several transmissions.** Transmissions count distinct Correspondence, never binding rows.
- **OUTCOME is item-specific in V1.** An OUTCOME event and any outcome value name one reported item of the case (422 `OUTCOME_ITEM_REQUIRED`). Mixed outcomes are separate item bindings; a reinstatement is a new binding, and the removal stays.
- **Silence is never an outcome.** No reply, elapsed time or missing record creates or implies one; without an outcome binding, the outcome is unknown.
- **Supersession corrects without altering history.** A correction is a new binding naming the earlier one of the same case and message, with at most one successor (409 `BINDING_ALREADY_SUPERSEDED`). The earlier binding and the message never change.
- **Content is untrusted.** Captured text is data shown as plain text — never HTML, a link to follow, an instruction or classifier input.
- **Zero external actions.** No mailbox connector, Gmail/Hostinger, SMTP/IMAP, send, reply, read-marking, uploader contact, submission, retraction, counter-notification, Drive write or outbound request exists.
- **No readiness in P4C.** Nothing computes or implies G1–G7, READY_FOR_SIGNER, readiness, a CaseFact or a later-phase record.

Implementation rules:

- Capture (`POST /correspondence`; Idempotency-Key, no If-Match, no ETag):
  - The agency exists (422) and is unarchived (409).
  - Every contracted field is stored exactly (no trimming or normalization); a NUL in `bodyText` is 422.
  - `bodySha256` = SHA-256 of the recorded body text only, labelled "SHA-256 of the recorded body text", never a raw-MIME hash. `sourceIdentityHash` is null.
  - `occurredAt` only as supplied (R7 storability), never from `headerDateRaw` (raw text, never parsed) or from `createdAt` (the ingestion instant, "Recorded in TB"). `timestampPrecision` as supplied (default `UNKNOWN`).
  - 422 `CAPTURE_POSTURE_UNSUPPORTED` only for: `RAW_SOURCE` without `rawSourceId`; an `OBSERVED_IN_RAW_MIME` attachment without a raw source; `EXCERPT` with `FULL_MESSAGE`.
  - Raw and attachment sources must apply to the agency (`source-scope.ts`, target Agency; case-scoped sources are refused). Attachment states never change.
  - The list is in capture order, as the summary DTO without the body. Reads write nothing.
- Binding (`POST /cases/{caseId}/correspondence-bindings`; the case's If-Match):
  - The case is unarchived. The message belongs to the case's agency (422 `CROSS_AGENCY_REFERENCE`). An item belongs to this case (422 `CROSS_CASE_REFERENCE`) and is unarchived (409).
  - Supersession refusals: another case's binding 422 `CROSS_CASE_REFERENCE`; another message 422 `REVISION_SCOPE_CHANGE`.
  - A binding moves the case's `rowVersion` and `contextRevision` once and makes the case history-bearing (a route correction is then 409).
  - No direction rule and no duplicate-binding rule. The list shows every binding, superseded ones included, newest recorded first.
  - Lock order: CaseRecord → ReportedItem (a capture: Agency → SourceReference).
- Audit: `CORRESPONDENCE_CAPTURED` and `CORRESPONDENCE_BOUND` keep identifiers, modes, states, the body hash and lengths. Subject, body, Message-ID, In-Reply-To, addresses, raw header date, limitations and interpretation are kept only as their length; attachment file names are not copied.
- UI:
  - Posture labels "Raw source captured", "Copied full text", "Excerpt", "Operator reported" — never verified/authentic email or confirmed transmission.
  - "Occurred" apart from "Recorded in TB".
  - AS_SENT copy: "Recorded as a past transmission. Capturing this record did not send anything." No Send button; never "Sent by Takedown Bureau application".
  - "Recorded outcome", never "Current platform status".
  - Captured text as plain text (`<pre>`, never `dangerouslySetInnerHTML`).
  - The binding form preselects no event and offers only this case's items and the agency's messages.
- Error codes: P4C implementation codes `CAPTURE_POSTURE_UNSUPPORTED`, `OUTCOME_ITEM_REQUIRED` and `BINDING_ALREADY_SUPERSEDED` (free-string `code`, contracted statuses). `smoke:p4c` writes records and runs only in CI.

## Production context (P4D, R11 PASS; VERIFIED_COMPLETE, merged to `main`; details `docs/verification/p4d/P4D_PRODUCTION_CONTEXT.md`, §29–§30)

Persistent rules (never weaken; UI copy follows them):

- **Context = recorded input, not a legal conclusion.** `getProductionContext` assembles what a case records for one task. It is never a G1–G7 decision, READY_FOR_SIGNER, legal approval, an ownership, permission or infringement finding, current authority or signer eligibility.
- **Exact case isolation.** Only the path case's own records; another case's selection or binding is 422 `CROSS_CASE_REFERENCE`; nothing of one case appears in, supports or changes another case's context.
- **Exact authority pinning.** The authority block is exactly the named selection and the chain it pinned. Never the route's default signer or preferred coverage, a newer version, coverage or source revision, or a union.
- **No latest/default substitution.** Nothing is chosen for an omitted selector: not the case's current selection, the latest NMI or any AS_SENT binding.
- **MISSING stays missing; CONFLICT stays conflict.** A MISSING fact is listed as missing, never false or negative; recorded conflicts are listed, never resolved or dropped; nothing is filled in to close a gap.
- **Correspondence posture stays visible; `*_AS_SENT` does not imply a verified package.** Capture mode, body role and attachment observations as recorded; OPERATOR_REPORTED keeps its limited posture.
- **Valid when recorded ≠ applicable to this case now (R14-AUD-001, R14-AUD-009, R14-AUD-010).** Every source a context lists is rechecked against this case in the read's snapshot with the direct-citation rules — its agency, case scope, bound legal subject and owner, including another owner's material recorded later outside the case. A citation is checked against its own record's target when written: a capture (bound into several cases), a mandate version's sources and a whole-mandate event's source (a mandate spanning several routes) against an agency only, the case's own citations against the case before another owner may have started to use the source. One that does not apply is listed with a conflict — `CORRESPONDENCE_SOURCE_NOT_APPLICABLE` per citation of a selected message, `SOURCE_NOT_APPLICABLE` once per source for every other citation — never as clean support, never dropped, rewritten or refused. Nothing about the citing records or the source changes, and it decides nothing about authority (the selected chain stays exactly as pinned), rights or any gate.
- **One consistent snapshot per read; a complete dependency closure; the digest is never merely `Case.rowVersion`.** Its definition identifier names the context semantics (R14-AUD-013, ADR-0007): a preview read under an earlier definition never authorizes a write.
- **No readiness, no writes, no external action.** A read writes nothing (no audit event, idempotency record, revision or row version) and sends, fetches, contacts, drafts or signs nothing.

Implementation rules:

- One REPEATABLE READ transaction per read (`modules/production`), the case row first (it fixes the snapshot); plain SELECTs only. The test seam `CONTEXT_READ_OBSERVER` (no-op in the app) runs right after the case row.
- Query exactly as contracted: required `taskType` and `generationMode`; optional `authoritySelectionId` and `parentBindingId`; `priorBindingIds` repeated once per id (≤100, each once — 400). Refusals:
  - INITIAL with a parent or priors: 422 `SELECTOR_NOT_FOR_TASK`.
  - Unknown selector: 422 `REFERENCE_NOT_FOUND`; another case's: 422 `CROSS_CASE_REFERENCE`.
  - A parent that is not NMI: 422 `REPLY_PARENT_REQUIRED` (NOT_NMI).
  - A prior not `*_AS_SENT`: 422 `PRIOR_BINDING_NOT_AS_SENT` (direction never counts).
  - A corrected binding: 409 `BINDING_ALREADY_SUPERSEDED` naming the correction, never used in its place.
- Party: the agency from the case; owner and legal subject only through the bound route; the signer only from the named selection.
- Intake: unarchived records in recording order; an archived one only when an included record names it (conflict `ARCHIVED_RECORD_REFERENCED`).
- Facts: chain heads only; supports exactly as recorded for that revision, never re-pointed.
- Sources: exactly the closure's revisions (never the registry, never a newer revision); `policySources` only POLICY_REFERENCE sources LINKED to the case; manifest text over 5,000 code points is not listed (missing item), never cut.
- Authority events: whole-mandate and pinned-coverage events of the pinned mandates, whenever recorded, in recording order.
- Correspondence: one row per selected message.
- Listed sources (R14-AUD-001, R14-AUD-009, R14-AUD-010; `modules/production/context-sources.ts`): `sourceCitations` (pure) names every citation by a record of the context — kind, citing record, field — in a fixed order: the case's canonical binding and packet sources, its case source links, fact supports, mapping and selection bases, the pinned versions' primary, additional and signed-date sources, the coverage bases, the selected signer's coverage-signer sources, whole-mandate and coverage-scoped event sources, a selected message's raw and attachment sources. `readContextRows` reads exactly the cited sources (never the registry or a directory record's canonical source the context does not list), and `currentSourceApplicability` evaluates each once per read with `applicabilityProblem` (`source-scope.ts`: `scopeProblem`, then `otherOwnerUsing` when the case has an owner — the read-only form of `assertSourcesUsable`; plain reads, no lock, write or audit) against the case (its bound route, or none: a subject-scoped source is then `CASE_SUBJECT_UNBOUND`, no subject guessed). A selected message's citations: one `CORRESPONDENCE_SOURCE_NOT_APPLICABLE` per citation (fieldPath `correspondence[i].rawSourceId` / `correspondence[i].attachmentsManifest[j].sourceId`). Every other citation: one `SOURCE_NOT_APPLICABLE` per source at its manifest entry (`sources[i]` / `policySources[i]`), naming the reason (e.g. `SOURCE_SCOPE_UNRESOLVED: SCOPED_TO_OTHER_SUBJECT`, `CROSS_OWNER_REFERENCE`; never the other owner) and each other citing record in words, sorted, at most 20 named and the rest counted. Each citation is reported once. The source stays in the manifest and the closure; it is no DRAFTING gate; prompts freeze it and validations report it (`CONTEXT.CONFLICTS`). Applicability is never stored on a record.
- DRAFTING: refused while a blocking code is missing — `CASE_ROUTE_UNBOUND`, `AUTHORITY_SELECTION_NOT_SELECTED`, `REPORTED_ITEMS_ABSENT`, `WORKS_ABSENT`, `USE_MAPPINGS_ABSENT`, `REPLY_PARENT_NOT_SELECTED`, `PRIOR_AS_SENT_NOT_SELECTED`. The refusal is 422 `REPLY_PARENT_REQUIRED` (NOT_SELECTED) or `DRAFTING_INPUT_MISSING`, naming every blocking code. PREPARATION returns the same context with its gaps. Over a contracted bound: 409 `PRODUCTION_CONTEXT_TOO_LARGE`, never cut.
- Dependencies: one per record of the closure, in `(entityType, entityId)` order.
  - Fingerprint: SHA-256 of TB canonical JSON v1 (`infrastructure/integrity/tb-canonical-json.ts`, the frozen helper's port) of the record's semantic content. Operation metadata, archive reasons, a work's notes and the route's defaults are left out. The existence of a source's newer revision and of successor versions/coverages is included, and so is another owner's use of any listed source, whichever record cites it (`otherOwnerMaterial: true` on that source only, present only then; R14-AUD-001, generalized by R14-AUD-010) — the only applicability input outside the closure (the recorded-scope result follows from the source revision, the case, its route and association), so any change in whether a listed source applies changes the digest, even with an unchanged source row, head and `contextRevision`.
  - `dependencyDigest`: SHA-256 of `{algorithm TB-PRODUCTION-CONTEXT-DIGEST-v2, contract, PFC version, scope (priors sorted), [entityType, entityId, fingerprint]}` (since R14-AUD-013, ADR-0007 ACCEPTED at R14 final; before it, v1). The identifier names the context semantics, not only the encoding. It changes whenever identical rows, scope, contract and PFC identifier could give a materially different context: a new applicability, conflict or gap derivation, closure interpretation or another evaluator change no fingerprint reflects. It never changes for a refactor with the same output, a UI, CSS, test, logging or performance change. A wire release is no substitute.
  - One definition for every read and rebuild: no option, parameter or fallback, and the v1 definition only in test code (the oracle `tests/support/context-digest-oracles.ts` and the compiled smokes' recomputation). Stored digests stay as recorded, never recomputed or upgraded, and `contextRevision` never moves for a deployment.
  - `rowVersion` is a diagnostic only.
  - A new dependency kind of the context must join the closure and its tests.
- No ETag, If-Match or Idempotency-Key; `Cache-Control: no-store`.
- UI (`apps/web/src/app/cases/production-context.tsx`):
  - The boundary statement.
  - Nothing preselected; the pickers offer only this case's NMI bindings and bindings recorded as sent.
  - Missing and conflict lists in their own neutral treatments.
  - A source the context records as not applicable is marked where listed: the tag "Not applicable to this case’s scope" beside each of its citations the page shows (a message's raw source or attachment; an authority or mapping citation) and, in both source lists, "Recorded source is not applicable to the current Case scope." — never invalid evidence, unauthorized, no authority, infringement or gate wording.
  - "Selected for evaluation; not a G1 decision."
  - Posture beside each message and captured text as plain text.
  - After a requested read, focus moves to its outcome.
  - No generate, approve, ready, sign or send action.
- Error codes: P4D implementation codes `SELECTOR_NOT_FOR_TASK`, `REPLY_PARENT_REQUIRED`, `PRIOR_BINDING_NOT_AS_SENT`, `DRAFTING_INPUT_MISSING`, `PRODUCTION_CONTEXT_TOO_LARGE` (free-string `code`, contracted statuses). `smoke:p4d` writes records and runs only in CI.

## Prompt snapshots (P4E, R12 PASS; VERIFIED_COMPLETE, merged to `main`; details `docs/verification/p4e/P4E_PROMPT_SNAPSHOT.md`, §29–§30)

Persistent rules (never weaken; UI copy follows them):

- **Prompt snapshot ≠ notice or NoticeCandidate.** A prompt is input for a later drafting step outside the application (a person, or a drafting tool the operator chooses). It is never a notice, NoticeCandidate, approval, readiness decision, signature or transmission.
- **Prompt snapshot ≠ legal conclusion.** Nothing in it decides G1–G7, READY_FOR_SIGNER, ownership, permission, infringement, current authority or signer eligibility; the prompt says so to its reader.
- **Deterministic rendering.** One pure renderer, template `TB-PROMPT-TEMPLATE-v1` (an implementation identifier: not a wire or PFC release, no legal or policy approval): no clock, randomness, locale, environment, database or network; the same context gives byte-identical text; unit tests pin the bytes. Any change to the rendered structure or wording needs a new template identifier.
- **Exact context freeze.** A snapshot stores exactly the context its generation rebuilt — equal to the reviewed read, or nothing is stored — with its revision, digest, dependency manifest, source manifest, missing items, conflicts, rendered text and SHA-256. Nothing is recomputed on read.
- **Exact dependency freeze.** `dependencyManifest` is the context's closure with its fingerprints as of generation; later changes never touch it.
- **Stale context is refused.** The request names the reviewed revision and digest; any difference is 412 `CONTEXT_CHANGED` `{field}`, including a digest of an earlier digest definition (R14-AUD-013) — nothing written, nothing rebuilt silently, nothing retried. The page requires reading the current context before another generation.
- **No AI provider.** No AI-provider, network, mail or Drive call in the prompts module or pages, no provider SDK in any manifest (tests guard all three).
- **No G1–G7, readiness, READY_FOR_SIGNER, signature or external action.** The signature stays human and pending (HUMAN_PENDING): exactly one `[PENDING AUTHORIZED SIGNER — FULL LEGAL NAME REQUIRED]` slot; no legal declaration text (`[REVIEWED DECLARATION TEXT REQUIRED]` instead — a reviewed declaration needs human approval and is never invented); generating sends, fetches, contacts or signs nothing.
- **Untrusted content delimited.** Recorded text appears only in the case-data block as JSON string values between marker lines carrying the SHA-256 of that block; the prompt names instruction-like text there as quoted case content.
- **Historical snapshots immutable.** No update or delete, no ETag; a new generation is a new version; a replay returns the stored snapshot.

Implementation rules:

- `generatePrompt` (`POST /cases/{caseId}/prompts`; Idempotency-Key, no If-Match): the body is parsed against the contract, then `promptScope` (a prior named twice 422; a parent or prior with INITIAL 422 `SELECTOR_NOT_FOR_TASK`), then the claim. One SERIALIZABLE transaction (`modules/prompts/prompts.service.ts`):
  - `lockCase` FOR UPDATE (404; archived 409) → the expected revision → the P4D rebuild (`readContextRows` + `assembleContext`, its selector refusals unchanged) → the revision and the digest again (412 `CONTEXT_CHANGED`) → `assertDeliverable` (the P4D bounds and DRAFTING gate, shared with `getProductionContext`) → the source manifest and snapshot bounds (409 `PROMPT_TOO_LARGE`) → version MAX+1 per case and task under the case lock → the renderer and its bound (over 1,000,000 code points 409 `PROMPT_TOO_LARGE`, never cut) → `exactTextSha256` → one insert, one audit event, commit.
  - SERIALIZABLE matters: a dependency write that never locks the case (an authority event locks its mandate) waits for the snapshot. The test seam `PROMPT_GENERATION_OBSERVER` (`afterCaseLock`, `beforeInsert`; no-ops in the app) serves the consistency tests.
  - The case row is locked, not changed (no `rowVersion` or `contextRevision` move); a prompt makes the case history-bearing (`PROMPT_SNAPSHOT` in `HISTORY`: a route correction is 409, the case cannot be deleted).
  - `sourceManifest` = the context's `sources` + `policySources`, each entry as listed, by source id — never the registry or a newer revision.
  - `promptSha256` = SHA-256 of the exact UTF-8 bytes (the frozen helper's `exactTextSha256`; no trimming or normalization).
  - Audit `PROMPT_GENERATED`: identifiers, versions, digests, the prompt SHA-256, selectors, counts and lengths — never the prompt, context or captured text. The idempotency record keeps `{meta}` and the snapshot id (`WriteOptions.replayRecord`); a replay reads the stored snapshot back, even after the case changed; the same key with another body is 409.
- `listCasePrompts`: this case's snapshots (404 unknown case), newest first, summaries only (no prompt text, context or manifest); `q` = exactly an id, a digest or a prompt SHA-256. `getPrompt` (`GET /prompts/{id}`): global by id, exactly as stored; reads write nothing.
- Renderer (`prompt-renderer.ts`): header; PART 1 rules R1–R14; PART 2 task (INITIAL / NMI_REPLY — the named parent answered from its literal questions, priors at their recorded posture) and mode (PREPARATION with `[NEEDED: …]` markers; DRAFTING "not readiness, a review or a gate decision"); PART 3 every missing item and conflict as recorded; PART 4 the semantic case data (no operation metadata, archive reasons or work notes) as sorted-key JSON between the markers; PART 5 what to return (draft with one pending slot, document plan, ask dispositions, review notes).
- UI (`apps/web/src/app/cases/prompts.tsx`):
  - History: summaries, the boundary line.

## Notice candidates (P4F, R13 PASS; VERIFIED_COMPLETE, merged to `main`; details `docs/verification/p4f/P4F_NOTICE_CANDIDATE.md`, §28–§29)

Persistent rules (never weaken; UI copy follows them):

- **Candidate = exact unsigned draft artifact.** The subject, body, envelope and prepared-document plan drafted outside the application — by a person or a drafting tool the operator chose — from one prompt snapshot of its case, imported exactly for later validation and human review. Storing it proves nothing about its prose. UI: "This is an unsigned draft artifact. It is not approved, signed, ready, or sent."
- **Candidate ≠ legal conclusion, approval, G1–G6 result, readiness or READY_FOR_SIGNER.** Nothing about a candidate decides G1–G7, READY_FOR_SIGNER, legal sufficiency, ownership, permission, infringement, current authority or signer eligibility, and no candidate, version or state implies any of them (a later version is not more valid, approved or ready).
- **Exact PromptSnapshot binding.** A candidate names exactly one prompt snapshot of its own case (another case's is 422 `CROSS_CASE_REFERENCE`); its task is the prompt's. Nothing latest, newest or current is substituted, and no freshness is required at import: the draft records what was drafted from that exact snapshot. A PREPARATION prompt's candidate is stored as draft material only.
- **Exact body, envelope and document plan.** Every text is stored exactly as supplied — no trimming, newline rewriting, Unicode normalization or sanitizing; a NUL is refused before any claim. The envelope's thread is exactly the prompt's parent binding (none when the prompt named none) and its sender exactly the intended mailbox of the selection the prompt pinned; recipients are stored as entered and nothing is sent. A document plan is a plan: exact source revisions that apply to the case, a SHA-256 only as recorded on that revision, PREVIOUSLY_SUPPLIED only for a source that a prior transmission in the prompt's context records among its captured attachments; no state means attached, uploaded, supplied or sent, and there is no ACTUALLY_ATTACHED.
- **HUMAN_PENDING only.** `signatureState` is always HUMAN_PENDING (not a request field; SQL CHECK backstop). Nothing inserts a signer name, signs or adopts. Whether the body carries the `[PENDING AUTHORIZED SIGNER — FULL LEGAL NAME REQUIRED]` slot exactly once is the later validator's rule, not import's (AC-047: the draft is kept for correction).
- **Exact artifact hash.** `bodySha256` = SHA-256 of the exact UTF-8 bytes of the body. `artifactSha256` = SHA-256 of TB canonical JSON v1 of `{algorithm TB-CANDIDATE-ARTIFACT-v1, subject, bodyText, envelope {from, to, replyTo, parentBindingId}, preparedDocuments in stored order {sourceId, purpose, state, fileName, contentSha256, disclosureReview, limitations}, signatureState HUMAN_PENDING, signatureSlot}` — never an id, the case, prompt, parent, version, task, authoring tool, reasons, supersession or times. One changed character or a reordered plan is another artifact; changing the object needs a new algorithm identifier.
- **Immutable revisions.** A candidate's content never changes: no PATCH or delete, no ETag. A revision is a new candidate naming the one it revises — the same case and task, only the latest version of a chain (409 `REVISION_NOT_HEAD` naming it: no fork); the revised row stays byte-identical.
- **Supersede ≠ retraction.** "Supersede this draft artifact" records once, with a time and a reason, that a candidate is no longer the active draft artifact. It deletes, edits and creates nothing, contacts no platform and retracts nothing previously sent. UI: "Superseding marks this candidate as no longer the active draft artifact. It does not contact the platform or retract anything previously sent."
- **Case isolation.** A candidate is read and written only through its own case; nothing of one case appears in, supports or is used by another; candidate pages are rebuilt per case (React `key`), and another case's candidate is shown like an unknown one.
- **No AI provider, no validation or readiness, no external action.** No AI-provider, network, mail or Drive call in the candidates module or pages and no provider SDK (tests guard); importing calls, fetches and contacts nothing. Nothing validates, assesses, gates, exports, signs or sends a candidate.

## Technical validation (P4G, R14 PASS — first PASS_WITH_ONE_CONTRACT_REMEDIATION, then PASS at R14 final after the read-back and three Astra-audit remediations; VERIFIED_COMPLETE, merged to `main`; details `docs/verification/p4g/P4G_TECHNICAL_VALIDATION.md`, §34–§40)

Persistent rules (never weaken; UI copy follows them):

- **Technical validation ≠ substantive review.** A ValidationRun records what the technical ruleset found for one exact candidate artifact against the current recorded context: exact bytes and hashes, the envelope and thread, the document plan, internal markers, recorded gaps and drift. It decides no G1–G6 gate (authority, rights, identification, evidence, permission or exceptions, exact-artifact consistency and traceability QA), no legal validity or sufficiency, no signer eligibility and no G7 (human adoption, signature and sending stay outside the application).
- **TECHNICAL_PASS ≠ G1–G6, ≠ readiness.** TECHNICAL_PASS means only "the configured technical validation rules executed and found no technical blocker or review-required technical issue under this ruleset" — never ready, READY_FOR_SIGNER, approved, legally sufficient, rights proven, permission reviewed, authority valid, a signature or permission to send. Every run records `semanticReviewRequired = true`. UI: "Technical checks only. This is not G1–G6 review, legal approval, readiness, signature, or permission to send."
- **Deterministic checks and heuristic signals apart.** DETERMINISTIC = exact comparisons of stored values (bytes, hashes, identifiers, recorded relationships, exact reserved tokens and template lines). HEURISTIC = a bounded, documented pattern scan of free text for a person to read — never a finding about what the text means, never a BLOCKER (also when the rule fails while running), never labelled deterministic. No rule decides arbitrary prose.
- **Exact artifact binding.** A run targets exactly the path's candidate — no latest version, parent or child followed; a superseded candidate is validated as the exact historical artifact it is — and the artifact the caller reviewed (`expectedArtifactSha256` = the stored one, else 412 `ARTIFACT_CHANGED`). Nothing is recomputed from client text, repaired or normalized.
- **Fresh dependency binding.** A run evaluates the CURRENT production context of exactly its prompt snapshot's scope (task, mode, selection, parent binding, and the prior bindings recovered from its frozen manifest) with the P4D reader, digest (`TB-PRODUCTION-CONTEXT-DIGEST-v2` since R14-AUD-013, ADR-0007), bounds and DRAFTING gate unchanged — never a second digest algorithm. A v1 preview digest is 412. `expectedDependencyDigest` must be the current digest (412 `CONTEXT_CHANGED`, never substituted; a named binding corrected since is the same 412). The commit rebuilds the context and refuses a changed one: no run is published against mixed snapshots. The run stores exactly the context, manifest and digest it evaluated.
- **Complete coverage manifest; NOT_EXECUTED ≠ PASS.** `coverageManifest` = all required rule ids, the executed ones, the not-executed ones (a rule that cannot run, is not run or fails) and `semanticReviewRequired: true`. A required rule never disappears; a not-executed rule is never passed and always has an issue; an ERROR run is never a pass and promotes nothing.
- **No CandidateAssessment, no readiness, no G7, no external action.** Validation creates no assessment, readiness, signature or export record and changes no candidate, fact or case record (the case row is locked, never changed); nothing is signed, adopted, sent, fetched or submitted; no AI provider, network, mail or Drive call exists (tests guard).

Implementation rules:

- Ruleset `TB-TECHNICAL-RULESET-v3` for new runs since P4H (`modules/validation/technical-ruleset.ts`; ADR-0010, ACCEPTED_BY_OPERATOR · INDEPENDENT_REVIEW_DEFERRED; before it `TB-TECHNICAL-RULESET-v2`, R14-AUD-003, ADR-0006 §8; an implementation identifier: not a wire or PFC release, no legal or policy certification, not a G1–G6 review version): v1's 29 required rules in a pinned order (24 deterministic, 5 heuristic: `SIGNATURE.SLOT_LOOKALIKE`, `SIGNATURE.ADOPTION_WORDING`, `SIGNATURE.NAME_AFTER_SLOT`, `WORDING.ATTACHMENT_CLAIM`, `MARKER.GATE_LABELS`); a pure engine (no clock, randomness, locale, environment, database or network). `MARKER.INTERNAL_IDENTIFIERS`' identifier strings are pinned in the ruleset (`INTERNAL_IDENTIFIER_STRINGS`, v3: v2's eight — `TB-PROMPT-TEMPLATE-v1`, `TB-CANDIDATE-ARTIFACT-v1`, `TB-PRODUCTION-CONTEXT-DIGEST-v1`, `TB-TECHNICAL-RULESET-v1`, `TB-TECHNICAL-RULESET-v2`, `TB-SCHEMA-API-v1.2.0`, `TB-SCHEMA-API-v1.3.0`, `PFC-YT-EMAIL-v1.1` — plus `TB-PRODUCTION-CONTEXT-DIGEST-v2`, `TB-TECHNICAL-RULESET-v3` and `TB-SCHEMA-API-v1.4.0`), never read from `CONTRACT_BASELINE` or another value that follows the active release; an identifier the application starts to use needs a new ruleset version (a unit test fails). Under v2 one named exception held, by operator decision (R14-AUD-013, ADR-0007 §7): the digest identifier `TB-PRODUCTION-CONTEXT-DIGEST-v2` stayed outside v2's unchanged vocabulary. R14-AUD-014's documented bounded limitation describes v2 runs: captured or operator-supplied free text can contain that literal and flow through context, prompt and candidate text, and v2 runs do not detect it (v3 runs do) — never claim the literal cannot appear. Runs recorded as `TB-TECHNICAL-RULESET-v1` or `-v2` stay exactly as recorded (read back, listed and replayed as recorded; never relabelled or re-executed). Any change to a rule's meaning, kind, severity or vocabulary, or to the inventory, needs a new identifier.
- Key rules: the exact pending slot exactly once in the body and never in the subject (it proves the count only); HUMAN_PENDING only; body and artifact hashes recomputed (`exactTextSha256`, `TB-CANDIDATE-ARTIFACT-v1`); the stored shape re-validated against the contract (no ACTUALLY_ATTACHED); the thread exactly the prompt's parent; the sender exactly the pinned selection's mailbox; a reply's recipient compared exactly with the parent's recorded Reply-To (or From) — REVIEW_REQUIRED only, never a recipient judgement; plan sources exist, apply to the case, are in the evaluated context, are the latest revision (never re-pointed), with a hash only as recorded and PREVIOUSLY_SUPPLIED only as recorded by a prior transmission; the reviewed-declaration placeholder, the input placeholders and the prompt's structural lines are deterministic BLOCKERs, exact internal identifiers REVIEW_REQUIRED; a PREPARATION prompt's candidate is a deterministic BLOCKER; the current context's missing items (DRAFTING-blocking codes BLOCKER, others REVIEW_REQUIRED), conflicts and drift since the prompt (REVIEW_REQUIRED) are reported, never resolved.
- Result: ERROR (a rule failed while running) > BLOCKED (any BLOCKER) > REVIEW_REQUIRED (any REVIEW_REQUIRED issue or any rule not executed) > TECHNICAL_PASS; WARNING and INFO never change it. NOT_EXECUTED / not-run rules → a REVIEW_REQUIRED issue with the reason; a failing rule → a diagnostic issue with the error's name only (BLOCKER for a deterministic rule, REVIEW_REQUIRED for a heuristic one); no stack trace or private content is stored, logged or audited. ## Candidate assessments (P4H, IMPLEMENTED_SELF_VERIFIED, MERGED_TO_MAIN — operator fast track, INDEPENDENT ASTRA REVIEW DEFERRED BY OPERATOR; merged by PR #12, merge commit `19a7cb2`; details `docs/verification/p4h/P4H_CANDIDATE_ASSESSMENT.md`)

P4H is self-verified engineering implementation, not independent assurance: never describe it, ADR-0008/0009/0010, R14-AUD-005 or R14-AUD-006 as independently verified.

Persistent rules (never weaken; UI copy follows them):

- **An assessment is one attributable G1–G6 review record, never a readiness decision.** A CandidateAssessment records, as the operator enters it, one review of one gate (G1–G6) of one exact candidate artifact at one evaluation epoch, with the linked sources it rests on. Recording is not counting: it is never readiness, READY_FOR_SIGNER, G7, a signature, notice adoption, legal approval or permission to send, and it never changes, waives or disposes of a technical validation run or issue (D-6: no waiver, disposition, override or rebinding exists). UI: "Recording a review decides nothing else: it is not G7, a signature, notice adoption, readiness or permission to send, and it changes no technical validation run."
- **Exact epoch binding (ADR-0008, R14-AUD-005).** E = (candidateId, artifactSha256, dependencyDigest, rulesetVersion): the path's candidate and its stored artifact (412 `ARTIFACT_CHANGED`), the CURRENT digest of its prompt snapshot's scope (412 `CONTEXT_CHANGED`, never substituted; a preview under an earlier contract is 412), the ruleset the server runs now (422 `RULESET_NOT_CURRENT`) and a recorded ValidationRun of exactly E (422 `VALIDATION_RUN_REQUIRED`) whatever its result. TECHNICAL_PASS is not required, and an assessment never turns REVIEW_REQUIRED into a pass.
- **Supports are this case's LINKED sources; a PASS rests only on sources that apply now (D-3).** Another case's link 422 `CROSS_CASE_REFERENCE`; a PAUSED or UNLINKED link 409; a PASS citing a source that does not apply to the case now 422 with its scope code (e.g. `CROSS_OWNER_REFERENCE`); HOLD, BLOCKED, MISSING and CONFLICT may cite it to record the problem. Every review cites 1–100 supports (D-5: no support-less review).
- **DOCUMENT_REVIEWED is never inferred (D-4).** AI_ASSISTED + DOCUMENT_REVIEWED → 422 `REVIEW_UNSUPPORTED` {reason `AI_ASSISTED_PERFORMER`}; a HUMAN or DOCUMENTED_EXTERNAL_REVIEW performer records it only as the operator's explicit statement of an actual review; nothing upgrades provenance from a source, link, file name or URL. `assessedAt` is the actual review instant as supplied (R7 storability), or null — never the recording time.
- **History is immutable; supersession is explicit (D-1, D-2).** No update or delete, no ETag. A successor supersedes the head of the chain of the same candidate and gate, across epochs; the predecessor and its rows never change; a second successor 409 `ASSESSMENT_ALREADY_SUPERSEDED`. Two captures of one gate may both stand as heads — nothing picks the latest. A superseded candidate may be assessed as the historical artifact it is and never counts.
- **Historical support read-back (ADR-0009, R14-AUD-006).** `getCandidateAssessmentSources` returns exactly the stored AssessmentSource rows of one assessment of this candidate — never re-pointed to a newer revision, filtered by the present link state or annotated with present applicability; the present CaseSource state is a separate read shown apart. Never parse audit events, remember a POST response client-side or query the database from the UI instead.
- **Case isolation.** An assessment is read and written only through its own candidate and case; another candidate's assessment is 404 like an unknown one; nothing of one case supports another.
- **No readiness here, no G7, no external action.** Recording an assessment derives no readiness and exports nothing: readiness and the unsigned export are separate operations (P4I, below) that evaluate the recorded assessments; nothing signs, adopts, sends, fetches or contacts; no AI-provider, network, mail or Drive call (tests guard).

- `captureCandidateAssessment` (`POST /candidates/{candidateId}/assessments`; Idempotency-Key, no If-Match; `modules/assessments/assessments.service.ts`): the contract body (422), then the request-only checks before the claim (`assessment-rules.ts`: a NUL, an unstorable `assessedAt`, a case source cited twice or an ask answered twice → 422 `VALIDATION_FAILED`; then D-4). One short SERIALIZABLE transaction:

  - the superseded assessment, when named (unknown 422 `REFERENCE_NOT_FOUND`, another case 422 `CROSS_CASE_REFERENCE`, another candidate or gate 422 `REVISION_SCOPE_CHANGE` {fields}, not the head 409);
  - each support (unknown 422 `REFERENCE_NOT_FOUND`, another case 422, not LINKED 409 `RECORD_STATE_CONFLICT`, a PASS on an inapplicable source 422 — `assertSourcesUsable`, target Case, which also checks the ask dispositions' sources) and the ask dispositions (exactly the prompt's parent binding, else 422 `ASK_PARENT_MISMATCH`);

## Readiness and the unsigned export (P4I, IMPLEMENTED_SELF_VERIFIED, MERGED_TO_MAIN — operator fast track; the final whole-system audit of `abc31fc` = HOLD, its blockers R14-AUD-015…020 REMEDIATED_PENDING_INDEPENDENT_REVIEW; details `docs/verification/p4i/P4I_READINESS_UNSIGNED_EXPORT.md` and `docs/verification/final-audit-remediation/FINAL_AUDIT_REMEDIATION_AUD015_AUD020.md`)

P4I and its final-audit remediation are self-verified engineering implementation, not independent assurance: never describe them, ADR-0011 or its revision as independently verified.

Persistent rules (never weaken; UI copy follows them):

- **READY_FOR_SIGNER is derived, current and pre-signature.** `getCandidateReadiness` derives it on every read from the current captured records; it is never stored (no table, column, flag, cache or `approvedAt`), never a legal approval, G7, a signature, an adoption, permission to send, a finding of ownership or infringement or a platform outcome. It means only "Ready for authorized human signer review": the candidate stays unsigned and unsent; `signatureState` HUMAN_PENDING and `externalAction` PROHIBITED are constants. UI: "Ready for authorized human signer review" with "This candidate remains unsigned and unsent. An authorized human must review, adopt, sign and send outside this application." and the qualifiers "Derived from current captured records.", "Not G7, not a signature, and not a send action.", "Source changes not captured by this system cannot be detected here."
- **One current epoch, derived by the server (ADR-0011 Decision 1).** E = (candidateId, stored artifactSha256, the CURRENT digest of exactly the prompt snapshot's scope — the P4D reader, `TB-PRODUCTION-CONTEXT-DIGEST-v2` — and the ruleset the server runs now, `TB-TECHNICAL-RULESET-v3`). A client never supplies E; nothing latest, default or replacing is chosen; a corrected named binding leaves no readable scope (GET 409 `BINDING_ALREADY_SUPERSEDED`, export 412 `CONTEXT_CHANGED`).
- **Status precedence; a nicer status never hides a stronger reason (Decision 3).** SUPERSEDED > BLOCKED (archived case, PREPARATION prompt, DRAFTING input missing, oversized context, artifact integrity, signature slot) > UNVALIDATED (no run) > STALE_REVALIDATION_REQUIRED (runs, none of E) > BLOCKED (a BLOCKED or ERROR run of E, a blocked gate) > STALE_REVALIDATION_REQUIRED (reviews of another epoch, a G1 review overtaken by a captured boundary) > REVIEW_REQUIRED (everything else) > READY_FOR_SIGNER, exactly when no reason code is present.
- **No waiver (D-6 stays deferred).** READY_FOR_SIGNER needs a counted TECHNICAL_PASS of E with every required rule executed and none not executed; no assessment, disposition, override or re-draft turns a REVIEW_REQUIRED run, a stored BLOCKER or REVIEW_REQUIRED issue or `PLAN.SOURCE_IN_CONTEXT` into a pass. Same-epoch runs (R14-AUD-015, Decision 4 revised): the runs of E latest first `(createdAt DESC, id DESC)`; a run that did not complete (ERROR, or a required rule not executed) is a diagnostic — earlier ones stay history and poison nothing (a later completed run recovers), the latest one counts and is never READY (no older PASS relied on); **completed** runs that disagree (result, coverage, deterministic issues) are `TECHNICAL_RUN_CONFLICT`: none counts, never the convenient or the latest PASS.
- **Six gates, non-compensatory (Decisions 6–8).** Per gate the heads of its chains at exactly E: none → UNASSESSED (`ASSESSMENT_STALE` with history), several → CONFLICT (never the latest PASS), one → its result; a PASS counts only when scope-confirmed, attributable (visible performer, rationale and scope text — at least one code point that is not white space, a control character or a default-ignorable code point; provenance not MISSING or CONFLICT), with 1–100 supports that are LINKED links of this case whose sources the current context lists as applying (else BLOCKED `ASSESSMENT_INTEGRITY_FAILED`). G6 is independent of the technical run; for an NMI reply it needs the reviewer's ask dispositions (at least one) of exactly the prompt's parent, each ask once, every disposition resolved and every cited source applying now — nothing is fabricated. A disposition is the ask's recorded status, never mere presence (R14-AUD-016, Decision 8 revised): `ANSWERED_SUPPORTED`, `ANSWERED_WITH_LIMITATION` and `NOT_APPLICABLE_WITH_REASON` are resolved; `REQUIRES_DOCUMENT`, `MISSING_FACT` and `LEGAL_REVIEW_REQUIRED` hold G6 (`G6_ASK_REQUIRES_DOCUMENT`, `G6_ASK_MISSING_FACT`, `G6_ASK_LEGAL_REVIEW_REQUIRED`), beside answered asks too; no text is read (no keyword rule); ask completeness is the reviewer's attributable record (`MATERIAL_SEMANTIC_AMBIGUITY`). Another candidate's assessments never count. Two chains of one gate at one epoch stay CONFLICT until the epoch changes (backlog: no reconciliation workflow).
- **Temporal freshness from captured boundaries only (Decision 9).** The pinned versions' and coverages' effective and expiry dates, the selected signer's coverage-signer dates and every uncorrected authority event (its instant, else its date). An instant stales the G1 review exactly when `assessedAt < e ≤ now`; a date D is the interval `[(D−1)T10:00Z, (D+1)T12:00Z)` in which it is D somewhere — a review or evaluation inside it is `TEMPORAL_BOUNDARY_AMBIGUOUS` (never a clean pass); a null or future `assessedAt` is never replaced by `createdAt` (`G1_REVIEW_TIME_UNKNOWN`); a selected start date ahead is `AUTHORITY_EFFECTIVE_DATE_NOT_REACHED`. Time alone never stales anything: no 30/60/90-day rule.
- **The unsigned export re-evaluates, hands over exact bytes and releases nothing stale (Decisions 14–17).** Only a candidate that is READY_FOR_SIGNER now, for exactly the artifact, digest and run the caller read; the stored subject, envelope and body byte for byte, both hashes, HUMAN_PENDING, `sendPerformed` false, the readiness evaluated and the instant. A replay of the same key re-evaluates — at an instant sampled after its reads, never the request's instant from before the claim and the replay lookup (R14-AUD-020) — and returns the historical response only while still READY_FOR_SIGNER with the same artifact, digest and run; otherwise the present refusal — the old body is never released. Labels UNSIGNED and NOT SENT; no send button.
- **No persisted readiness, no G7, no external action.** A readiness read writes nothing (no audit event, idempotency record, row version or context revision); an export writes one redacted audit event `EXPORT_UNSIGNED` and its idempotency record, nothing else (no export table, row or copy of the text); no signature capture, signer confirmation, adoption, send, email, SMTP, YouTube submission, Drive write, uploader contact, platform response or AS_SENT record exists; no AI-provider, network, mail or Drive call (tests guard).

Implementation rules:

- UI (`apps/web/src/app/cases/readiness.tsx`; imports only types from `@tb/contracts`): the "Readiness" section of the candidate page.
